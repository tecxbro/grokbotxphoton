1. **Per-provider-call execution boundary (blocking).** `ExecutionServices` currently has a claim value, but no callable per-child dispatch service, request identity, or way to atomically record a child outcome. WT-01 cannot guarantee per-call fencing for such a handler through the frozen interface alone. Promote the owned `executeChild(services, index, send)` design into the shared service interface. It must supply the request/child identity, execute the final synchronous authorization/claim check immediately before invoking the provider call, and persist returned outcome plus checkpoint together. Require feature modules to use it for every consequential SDK call. No external provider idempotency key is assumed.

   The current adapter is a WeakMap keyed by the exact injected `ExecutionServices` object, with no JSON selection or fallback. Host `ExecutionBinding.boundary` must be explicitly certified: `durable-children` uses that adapter; `single-call` is only for an audited handler that synchronously initiates exactly one provider call at entry, then serializes its result. Never certify a multi-call handler, lazy builder, streaming send, helper with internal writes, or handler that awaits before initiating the write as `single-call`. Generic F0 handlers are not automatically safe or activated. The adapter and all feature code are trusted in-process code, not a sandbox.
