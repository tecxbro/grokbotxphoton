2. Wire one `SpectrumOwner`, exactly one `SpectrumEventSource` **or** `NativeWebhookIngress`, and one `InboundPump`. `examples/wt-02/compose.ts` is a compile-only recipe. Call client startup, capture/inbox recovery, pump/outbox startup, then ingress, in the existing host lifecycle. During shutdown, stop the pump before closing the database; the owner's `beforeStop` hook stops/drains typing before closing the SDK. A warm-up or wake-only endpoint must never pass message payloads to ingress or establish another listener.
3. Supply explicit project/account/line-to-phone bindings, the current task/principal/generation lookup, the provider conversation-ID resolver, and the existing Grok notification binding. `ProviderContext` hashes opaque chat GUIDs to F0-compatible IDs; compose the same exported mapping with shared reference/resource resolution, retaining raw provider IDs. Do not assume a first line, parse synthetic IDs, or match poll choices by label.

Native webhook accepts only the documented `messages` JSON envelope; no Fusor/protobuf/wake-only shape is accepted. Route must pass raw bytes.
5. `InboundPump` reads configured active scopes, batches durable input and retries pending/expired-claim handoffs. `ExistingGrokTaskHandoff.notifyExistingTask` must have a bounded notification deadline and idempotent acceptance by handoff ID. Bind to a verified existing mechanism; actual deployment credentials/configuration are absent. The adapter must not interpret an accepted wake as `work.ack`.

## WT-01: explicit execution binding and operational continuations

F0 `ExecutionServices` lacks a persisted request ID/result revision/typing-job expiry. Supply `BindTypingExecution` returning `{requestId, resultRevision, expiresAt, assertCurrent}`. The validator must read the current outbox claim/fence, task generation/cancellation, context revocation and authorization immediately before control dispatch. Do not return the caller's idempotency key as a request ID. Expiry must be anchored to the original persisted job, never refreshed on retry. The transient typing recovery codec retires prior-process start work; it must not replay it.

`typing.begin/end` complete transient lease scheduling and return void without provider observations. They do not report that an indicator was rendered. `TypingLeases.responding` wraps active response work; call `waiting(ticket)` before long delegated work, and create a fresh lease when responding resumes. Actual replies/uploads must not wait for a typing promise. A hung SDK control remains uncertain and is reported on bounded shutdown.

Consume `HandoffRecord.eventIds` as distinct persisted typed inputs; preserve ownership/claim fencing in the existing `work.list/claim/heartbeat/ack` implementation. `InboundPolicy.continuation` must opt in only the feature events that should resume business work, such as a correlated poll/card selection. Receipts, typing and metadata default to no conversational wake. `CorrelationPending` rolls back the reducer transaction while retaining the inbox event for later resolution.

## WT-00: F0 storage and event contract limitations

- `Transaction.list` has a 1000-row bound and no continuation/filter cursor. WT-02 fails with `INBOX_PAGINATION_REQUIRED` when that bound is reached, rather than ignoring pending records beyond the first page. Add scoped keyset pagination or pending-inbox filtering before production scale. Provide ordered ingestion ordinals if same-millisecond arrival ordering matters; no provider order is invented.
- Existing `CheckpointRecord` is bound to execution requests and claims. WT-02 does not fabricate an outbox request/claim to save a provider cursor. It exports a durable-prefix barrier and reports the absence of a public resume cursor. Add an ingress checkpoint contract only when a public SDK recovery seam is available.
- F0 event metadata cannot hold all native attachment details/group actor fields or a capture pointer on every event; raw public snapshots retain those details, and `unresolved.quarantineId` points to a capture for unsupported content. Add a typed capture/provenance reference and safe metadata fields for downstream access without scanning files.
- F0 requires `content` on an `unsent` event and a sender on every message. This lane quarantines absent content/sender rather than inventing either. Rich contact fields and unregistered app/custom payloads also remain unresolved. Consider dedicated inbound schemas for these cases.

## WT-05 / WT-06 / native feature lanes: correlations and SDK coverage

`Correlations.poll` accepts only authoritative scoped poll/option references. The public 12.8.0 `PollChoice` contains a title, without its native option ID, and the public vote object does not identify the parent message. Missing/ambiguous mappings remain durable and unresolved. `recoverCaptures` can re-normalize a capture when the authoritative mapping becomes available; the router can promote an unresolved event with the same identity. Feature reducers own polls/votes/cards/session state and may throw `CorrelationPending` before correlation is complete. No poll/card business state was duplicated.

The pinned iMessage stream maps received messages, added reactions, attributable reads, poll votes/unvotes and supported dedicated-line group changes. It consumes several other native event kinds without exposing a public message: edits/retractions, removed reactions, delivered/failed receipts, poll option-added deltas and some unmappable records. It also hides raw event sequences and durable restart cursors. The lane can preserve typed F0 events when a future verified adapter supplies them, but cannot manufacture missing events or claim full native coverage. Request an approved public SDK seam/version update before requiring these events or zero-loss restart recovery. No advanced SDK client was constructed alongside Spectrum.
