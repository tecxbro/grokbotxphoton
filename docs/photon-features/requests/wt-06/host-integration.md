# WT-06 integration requests to WT-00

No shared contracts, migrations, registration, host wiring or dependencies were edited by WT-06.

1. Register `createCardsModule(options)` from `src/features/cards/module.ts` in the one shared registry. Execute its three handlers through the existing executor. Supply the executor's actual `requestId`, authorized resource resolver, transaction store and trusted scope-to-phone/native-space binding. Add public package exports if needed; WT-06 cannot edit the aggregate index or package metadata.

2. Capture an immutable expected card revision at request admission. F0 `app.update` has only card/session/layout; execution-time revision lookup cannot distinguish a delayed old intent. Supply `CardOptions.updateRevision(action, services)` from a durable admission binding, or add an expected-revision argument through a reviewed F0 contract revision. Missing binding returns `card_update_revision_required`. Never implement this callback as a lookup of the latest card revision. Fixture maps model admission only; they are not production persistence. Registration must include a test that the expected revision survives an executor restart.

3. Register actual universal/customized templates with exact allowed HTTPS origins. Customized templates require the real app name, Apple Team ID and extension bundle ID; App Store ID is optional. Live rendering is opt-in and requires installation evidence for the corresponding extension. No extension has been configured, installed or provisioned by this lane. In a multi-recipient deployment, the host must scope installation evidence to the actual recipients. A static template remains independent of a live template.

4. Universal `app()` accepts a URL, not an arbitrary layout. To update a universal card under F0, supply a real, side-effect-free template `updateUrl(layout, context)` mapping for the configured backend, or add a validated URL to the shared update contract. This function must not mutate an app backend: preparation occurs before the final fence check. Without the mapping, updates return `universal_update_url_required`; static sends still work. Customized cards use the pinned layout API directly. Image layouts reuse the supplied caption as the SDK-required image title; an empty caption with an image is rejected.

5. Implement the real backend protocol before mounting `createInteractionAdapter(...).accept` on the approved host. Supply its version/source and raw-body authentication/strict decoding implementation, including authenticated participant identity. The normalized assertion interface is internal, not a proposed external protocol. WT-06's HMAC fixture is explicitly test-only. Register the durable card-session/task/scope/participant/action/expiry/nonce binding with that backend over its own authenticated control path; the lane does not invent that path or claim it is deployed. The callback binding exists in the versioned checkpoint and must not be exposed to an unrelated principal. Callbacks are single-use per nonce. Further interactions need an explicit host-controlled binding renewal contract.

6. Mount the adapter without a second server, client, subscription or outbox. Do not forward unverified `app.messages` events to it as authenticated callbacks. F0 app-interaction events lack participant/nonce proof and are quarantined by the generic reducer. The configured adapter commits inbox/replay state, session transition and pending handoff in one transaction, then invokes the shared wake port. The shared dispatcher must retry pending handoffs after failed/unknown wake and re-check task generation/cancellation; callback replay intentionally does not send another wake.

7. Rehydration through `ResourceResolver.message` must return an actual original public SDK handle with matching provider-managed metadata. WT-06 never reconstructs a Message or injects serialized miniAppCardSession into it. Full SDK/cache restart restoration is unsupported unless Photon supplies a documented public restoration contract and evidence. Missing/changed metadata returns `requires_original_session`. Keep unknown/dispatching checkpoints for reconciliation; do not resend or replace a card to recover them.

8. Consume the extra registered `wt06.card-dispatch@1` codec for send markers and `wt06.card-session@1` for card state. Both reconcile uncertain dispatch as unknown.
