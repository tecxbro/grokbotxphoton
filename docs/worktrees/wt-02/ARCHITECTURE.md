# WT-02 runtime boundary

## Lifecycle and scoped provider access
`startSpectrumOwner` / `stopSpectrumOwner` wrap the retained idempotent SpectrumOwner lifecycle. `cloudSdkFactory` constructs exactly one pinned Spectrum instance and uses public `imessage(app).space.get(id, {phone})`. A receiver claim excludes a second stream or concurrent webhook path. `resolveProviderContext` validates project/account/line/chat, implements the current shared lifecycle contract, and exposes an owned `lookupNativeMessageState` extension. The shared transport interface does not yet declare that extension (CR-02-002).

`subscribeMessageEvents` is the new single stream adapter. Its `completion` rejects on persistence or receive failure, and the owner reports unready. The host must observe completion, invoke stop, and recover local captures before a new owner. It does not create independent feature subscriptions. The inherited SpectrumEventSource remains intact for compatibility; integration must select the new adapter when receipt acquisition is required, never run both.

## Ingress, ordering and durability
The stream snapshots public SDK values and writes the retained CaptureStore before normalization or receipt writes. The signed webhook path bounds raw bytes to 1 MiB, verifies v0 HMAC/timestamp before parsing, checks the exact native messages envelope and consistent account/line/chat routing, and waits for durable receipt and inbox acceptance before success. Tamper, unsupported alternate envelopes, mismatched routes and failed persistence return non-2xx. `app.webhook` is unsuitable as a durable acknowledgement boundary because its async callback is fire-and-forget in 12.8.0.

Both documented standalone `iMessage` and pinned SDK `imessage` spellings are accepted explicitly. Unknown content remains a captured unresolved event. Unknown top-level envelopes are rejected. No delivery-event subscription is invented. Standalone webhook read coverage is unverified: the official wire page documents a narrower inbound subset than the SDK message stream.

`normalizeInboundEvent` retains typed message/media/poll/edit/reaction/read/group data where the shared union permits it. Raw snapshots preserve additional fields. Event identity preserves the existing hash of scoped source ID, payload, direction, sender, provider time and captured metadata; local arrival time never participates. Preserving that key avoids duplicating previously persisted input when captures replay. Receipt evidence has its own stable identity and native metadata reconciliation never enters the conversational router. Missing direction becomes system/unresolved. Unknown poll identities, unsend content and richer unsupported payloads remain unresolved rather than guessed. No sequences or part IDs are parsed out of synthetic IDs. Native timestamps are retained when available; missing values stay null.

## Transaction, batching and wake
`routeInboundEvent` / `appendToBatch` persist each normalized inbox row. Runtime-owned shared transactions run registered synchronous reducers and create a durable handoff atomically. Reduction failures leave input pending or unresolved. `releaseReadyBatch` applies the existing 2000 ms quiet window to created inbound plain text only and preserves historical burst boundaries after restart; structured input reduces immediately. Missing route or correlation never drops input.

Outgoing echoes do not create work. Receipts, typing and group metadata cannot request a conversational continuation, even if a broad policy returns true. Preserve existing explicit opt-in continuations for correlated reactions, polls and app interactions, through registered reducers. This lane adds no poll/card business logic.

`configuredGrokWake` requires the existing deployment binding. `dispatchWake` sends only handoffId/taskId/generation after durable commit, retries pending/expired work on host scheduler ticks, and rechecks task generation before dispatch. Accepted wake is not work acknowledgement; workers must retrieve and claim the durable handoff through the existing shared work protocol. Cancellation during an external wake cannot retract the notification; retrieval must enforce current task authority. No verified deployment binding exists in this checkout.

## Receipt acquisition and native reconciliation
`observeReceipt` consumes exposed inbound read messages with their actual reader and provider timestamp. Native outgoing metadata can independently contribute delivered/read/rejected evidence. Neither a void SDK return nor isSent nor absence of sendErrorCode proves acceptance/delivery/read. Native snapshots provide no individual reader, so readerId stays null. Shared receipt parsing validates target scope; an optional trusted exact resource mapping correlates known targets. Early receipts carry target=null and the real providerTargetId. Explicit part IDs are retained; no part is invented.

The writer is injected as the shared StateStore.recordReceipt/receipt-service method. Each observation is appended before inbox acknowledgement. IDs are stable across observation time changes; partial write failures are safe to replay through the shared idempotent writer. No receipt database, migration, group membership denominator or conversational receipt wake is implemented here.

`lookupNativeMessageState` calls only scoped public space.getMessage for one known target. It verifies returned target/line/chat, bounds the wait (default 3000 ms, maximum 30000 ms), and keeps an in-flight slot while an uncancellable SDK call settles. A timed-out resolver cannot start a late query; subsequent calls cannot stack onto a still-pending target. Cancellation/timeout/missing/error returns no observations and never means unread. SDK I/O itself cannot be cancelled through this public API.

`reconcileReceiptTarget` accepts one trusted registered outgoing target from the host's durable work, acquires current metadata, and writes shared observations. The host supplies scheduling, durable target selection, and restart retrieval. The current shared store lacks receipt querying/correlation updates, so reattaching pre-registration evidence after restart remains an explicit integration blocker; the lane does not substitute a second ledger.

## Checkpoints and recovery
`advanceCheckpoint` requires every preceding local inbox event to be durable and invokes a synchronous persistence callback inside the same transaction. It is a local ingestion barrier, not an upstream sequence. `recoverStream` replays retained captures, replays receipt writes before inbox acceptance, preserves capturedAt, and aborts on storage failure. Unroutable captures remain returned as unresolved IDs.

Pinned Spectrum exposes no public durable restart cursor or connection-health callback. Within-process reconnect uses SDK-owned volatile catch-up state. Group events need a dedicated line; unattributable group reads and unresolved receipt targets may be dropped before Spectrum exposes them. No zero-loss or recovered-upstream-drop claim is made.

## Typing concurrency and execution APIs
`acquireTypingLease`, `releaseTypingLease`, and `expireLeases` expose the retained independently queued TypingLeases manager. Latest generation/token wins; old tickets cannot stop newer tickets. Revalidation follows delayed resolution. Timeout, cancellation, worker waiting, explicit connection loss and shutdown invalidate leases; restart starts idle. Hung SDK calls bound shutdown waiting and report uncertainty. The host must call connectionLost/connectionRestored from its own observed health and wire shutdown/waiting hooks; Spectrum does not supply a health callback here.

`executeTypingOperation` and `createTypingFeatureModule` use current public f0-services-2 resource resolution, claim checks and executeChild. The trusted binding supplies durable request ID/result revision/expiry. Work rechecks authority after awaits; asynchronous control dispatch revalidates again. Unavailable starts report UNAVAILABLE with no provider observations. Completion reports scheduling only, and all device visibility remains unknown. The inherited createTypingModule stays intact for its old host; new host registration belongs to integration.
