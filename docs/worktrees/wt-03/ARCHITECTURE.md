# WT-03 architecture

## Public execution path
`module.ts:createFeatureModule(options)` returns the frozen public FeatureModule with `owner: wt-03` and 13 keyed handlers. It parses inert bounded action JSON before property inspection, rejects a mismatched selected handler or missing context permission, then checks the active claim and injected provider scope/readiness. It is explicitly injectable into `registerFeatureModules`; no registry or host file is changed here.

`PublicTextMessageOptions` captures one existing provider owner, an authoritative binding (logical scope, native chat ID, native serving phone), SDK resource resolvers and the shared compiler registry. Executable callbacks come from host code, never JSON. It calls no lifecycle methods and creates no SDK client, model, router, outbox or receipt subscription.

## Files and behavior
- text.ts formats only text.send prose into intentional blank-line-separated bubbles and dispatches one shared child per bubble. Markdown and links bypass prose transformation; custom link titles are unsupported.
- streaming.ts claims the registered stream atomically through the shared streams domain before opening it. Generation, owner, task, full scope and expiry are checked. Input is consumed at most once with 16,000-character, 4,096-chunk and 30-second limits (or earlier expiry), cancellation-aware open/next races and nonblocking iterator cleanup. Shared child replay happens before source consumption. This is buffered fallback, not progressive native streaming.
- composition.ts validates inert content and provider wrapper/group constraints, resolves builders before effects, and delegates non-owned content families to exactly one registered compiler. Structured text is preserved literally. Each compose item is a child. A group is one opaque child, never a transaction or a group-chat creation request. No sibling feature imports exist in the new public path.
- targets.ts resolves shared authoritative references, verifies native IDs/line/chat and actual SDK direction, and restricts mutation to principal-owned outbound records. Reaction removal requires a real outbound reaction plus the matching authorized parent SDK handle. message.get refreshes through the containing Space.getMessage only after authorization and revalidates the returned identity. Supported bounded text/Markdown/link content is returned; other content returns real metadata without fabricated media JSON.
- replies.ts uses target.reply with a public SDK builder. reactions.ts uses target.react and target.unsend on the actual reaction handle. edits.ts enforces content eligibility, retraction and 15-minute edit / 2-minute unsend windows; other provider constraints remain provider-enforced. mark-read.ts requires inbound direction and invokes target.read on the authorized conversation.
- sdk.ts defines trusted configuration, stable parent/child identities, native checks, result mapping and shared child dispatch. Returned resource IDs are local hashes mapped to actual provider IDs in the shared references domain. No replacement IDs are generated for void controls. SDK-returned messages are provider-accepted evidence only, never delivered/read evidence.
- voice-policy.ts exposes formatMessageBubbles and validateVoicePolicy over the fuller inherited conservative formatter. Names, acronyms, code, URLs, paths and commands are protected; prose uses natural lowercase, complete thoughts, a roughly 120-character target, preferred 150-character maximum, one short question and no em dashes. Coherent thoughts are never cut for length. Tone warnings remain available to the existing orchestrator; there is no rewriting model.

## Recovery and failure boundaries
Consequential calls exclusively use public executeChild in the new path. Stable key/digest identify each top-level child. The runtime returns persisted completed or unknown outcomes before invoking dispatch; WT-03 keeps no alternate execution journal. An unknown child stops later sends and returns reconcile-first. Earlier accepted references remain in partial results when a later child fails or is cancelled. Provider I/O is outside domain transactions. Reference-map failure after provider dispatch is conservatively unknown, never safely replayed.

Streams record single consumption before opening. Pre-send source/validation failures return failed/cancelled with retry never, while exceptions after space.send cross the runtime unknown boundary. Cancellation after dispatch cannot undo a send. No receipt observation is synthesized by mark-read. Provider void results remain executor-completed with empty references and observations.

## Compatibility and integration boundary
The inherited createTextMessageModule, legacy compiler/target/stream helpers and journal files are retained unchanged for their existing callers and 65 regression tests. They are not the public factory and are not registered in the frozen F0 host. The new path never calls that journal or private execution tables. Removing or adapting the inherited legacy runtime belongs to an explicit integration migration; this lane does not silently switch existing callers.

Contract integration is tested with the shared in-memory public-services fixture; it proves the feature/service seam, not production SQLite recovery. Production host registration, durable public-services implementation and real handle/registry adapters still need integration in the designated integration worktree. Activation and live sends were not performed.
